# BurstTrigger — 장전식 증강 조립 가이드

`Iteration` 계열처럼 **장전했다가 연달아 쏘는** 증강을 위한 트리거.
코드를 안 짜고 인스펙터 조립만으로 만든다.

```
장전(쿨타임) ──▶ 탕 · 탕 · 탕 · 탕 ──▶ 장전 ──▶ ...
                 ├─간격─┤
```

---

## 1. 칸 두 개

```
Burst Trigger
  Count      값 0 · 배수 1        한 번 장전에 몇 발  (시트 수량)
  Interval   값 0 · 배수 0.04     발 사이 간격        (쿨타임 × 0.04)
```

`Scalable` 이라 두 가지로 쓸 수 있다.

| 적는 법 | 뜻 |
|---|---|
| 값 `0.12` · 배수 `1` | **고정 0.12초.** 레벨이 올라도 안 변한다 |
| 값 `0` · 배수 `0.04` | **쿨타임 × 0.04.** 쿨타임 3초면 0.12초 |

**기본은 배수 방식을 쓴다.** 쿨타임 감소 하나가 재장전과 연사를 같이 당겨주기 때문이다.
간격에 시트 칸을 따로 안 만들어도 레벨업이 반영된다.

> 간격은 최소 0.02초로 막혀 있다. 0을 허용하면 프레임 수만큼 쏜다.

---

## 2. Iteration 조립

```
Trigger     BurstTrigger
              Count       0 × 1        ← 시트 수량이 곧 장탄
              Interval    0 × 0.04
              No Target   Hold         ← 적이 없으면 탄을 안 쓴다

Targeting   NearestTargeting
              Range Override  0 × 1    ← 시트 사거리

Delivery    ProjectileDelivery
              Projectile Prefab   " i " 투사체
              Speed               14
              Pierce              0 × 1
              Life Time           3

Effect      DamageEffect
```

시트는 이렇게 채운다.

```
id         레벨  피해량  쿨타임  사거리  수량
ITERATION   1     8      3.0     7      4
ITERATION   2     9      2.9     7      4
ITERATION   3    10      2.8     7      5
ITERATION   4    18      2.4     8      6     ← 비약
```

> 기획서에는 반복 횟수가 **유지시간**으로 적혀 있는데, 코드는 **수량**을 본다.
> 유지시간은 초 단위 칸이라 개수로 쓰면 단위가 거짓말이 된다. 시트에서 수량 칸에 옮겨 적을 것.

---

## 3. 밸런싱 — 장탄을 늘리면 DPS 가 어떻게 되나

```
사이클 = 쿨타임 + (장탄 - 1) × 간격
DPS   = 장탄 × 발당피해 ÷ 사이클
```

발당 10 · 쿨타임 3초 · 간격 0.12초 기준:

| 장탄 | DPS |
|---:|---:|
| 1 | 3.3 |
| 2 | 6.4 |
| 4 | 11.9 |
| 8 | 20.8 |
| 16 | 33.3 |
| ∞ | **83.3 (상한)** |

**장탄을 아무리 늘려도 `발당피해 ÷ 간격` 을 못 넘는다.** 쿨타임이 사이클에서 차지하는
비중이 0으로 수렴하기 때문이다. 이게 이 트리거의 안전장치다 — 후반에 혼자 폭주하지 않는다.

### 어느 스탯이 잘 먹히나

```
발당 피해   항상 선형. 장탄과 곱해져서 언제나 유효
장탄        수익 체감. 상한에 점근
쿨타임      장탄이 적을수록 잘 먹힌다
간격        장탄이 많을수록 잘 먹힌다. 상한 자체를 올린다
```

쿨타임 3 → 2 로 줄였을 때

```
장탄 2    6.4 → 9.4   +47%
장탄 8   20.8 → 28.2  +35%
```

간격 0.12 → 0.06 으로 줄였을 때

```
장탄 2    6.4 → 6.5    +2%
장탄 16  33.3 → 41.0  +23%
```

**장탄과 쿨감은 상충하고, 장탄과 연사는 증폭한다.** 그래서 어느 것을 올릴지가
빌드마다 달라진다 — 하나만 계속 올리는 게 정답인 증강은 재미가 없다.

간격을 쿨타임 배수로 두면 이 상충이 완화된다. 쿨감이 양쪽을 다 당기기 때문.

---

## 4. 동작에서 알아둘 것

**매 발이 파이프라인 전체를 다시 탄다.**
타겟팅도 다시 돌기 때문에 "쏠 때마다 그 순간의 최근접" 이 저절로 나온다.
`MultiShot` 은 한 프레임에 여러 발을 뿌리는 것이라 감각이 완전히 다르다 — 산탄과 연사의 차이.

**`No Target Policy` 가 발사 중에도 먹는다.**

| | 발사 중에 적이 사라지면 |
|---|---|
| `Hold` | 탄을 안 쓰고 기다린다. 적이 나타나면 남은 탄부터 이어 쏜다 |
| `Consume` | 허공에 쏘고 탄이 준다 |

기획서의 `Iteration:break`(적이 없으면 폭발탄 쏘고 쿨타임 시작)는 `Consume` 쪽 확장이다.

**HUD 게이지가 탄창처럼 움직인다.**
발사 중에는 남은 탄 비율, 장전 중에는 채워지는 정도. 줄었다 다시 차는 모양이 곧 탄창이다.

**`Count` 를 1로 두면 평범한 쿨타임 무기와 같아진다.**
`CooldownTrigger` 를 이걸로 갈아끼워도 동작이 안 바뀐다는 뜻이라, 기존 증강에 연사를
붙여보고 싶으면 트리거만 교체하면 된다.

---

## 5. 내부 증강으로 가는 길

기획서의 `Iteration` 내부 증강은 손잡이를 하나씩 건드린다. 지금 트리거로 되는 것과 아닌 것:

| 내부 증강 | 지금 | 필요한 것 |
|---|---|---|
| `for` — N번째 강화 | ✗ | 발 번호를 아는 효과 |
| `while` — 조건 내 쿨타임 없음 | ✗ | 조건부 장전 생략 |
| `continue` — 처치 시 쿨감 | ✗ | 처치 이벤트 훅 |
| `break` — 적 없으면 폭발 | 🟡 | `Consume` + 무대상 분기 |
| `foreach` — 탐색 풀 순차 발사 | 🟡 | 타겟팅만 `SearchPool` 로 교체 |
| `do-while` — 회차 첫 발 강화 | ✗ | `for` 와 같은 기반 |

`for` 와 `do-while` 이 같은 기반(발 번호)을 쓰므로, 그것부터 만드는 게 효율이 좋다.
지금은 넣지 않았다 — Iteration 본체가 굴러가는 걸 보고 정하는 게 맞다.
